# #16：CSV 批次引用、撤销与可选本地归档

任务 #16／S6.4 的 Schema 与行为方案；源码、隔离验证及后续原生交互／页面验收已完成。旧 provider 不因普通启动自动升级，详细证据层级见 [验收清单](../acceptance-reconciliation.md)。

## 原有问题

`import_batches` 只保存该次新增量，`provider_records` 的 owner 是首次写入批次。现有去重保留文件内合法重复的出现次数，但没有记录其他批次的完整引用，不能删除某批次 owner 的全部记录来实现撤销。

## 增量结构

保留两张原表及原值，新增：

- `provider_batch_tracking`：`source/hash` 主键，完整文件的行数、原始量、精确计费量。标识已具有完整引用信息的批次；撤销后保留 marker，以区别旧体系 owner。
- `provider_batch_rows`：`source/hash/row_number` 主键，指向 `record_hash/record_row_number` 的一个物理 occurrence。为引用目标建立反向索引。

本机历史库不改变。原始量为整数 bytes，计费量沿用精确十进制 TEXT，不转浮点、不按倍率重算。

## 迁移边界

新 provider 库可以建立完整结构；已有库不因普通启动静默启用新结构。提供显式准备／备份升级入口，保留原两表逐值数据。旧批次不补 marker、不猜引用，其物理记录受保护，旧批次撤销不可用并说明原因。已有 provider 的升级按具体使用需求执行，不作为剩余必做验收。

## 导入和撤销

1. 新体系批次保存完整文件的每个 occurrence 引用，包括零新增的完全重叠文件。相同来源和文件 hash 已有活跃批次才算重复提交。
2. 已有多重集去重和冲突拒绝保持；不按时间范围或节点名称推测重复身份。
3. 撤销预览展示来源、批次、删除／保留记录数和各自精确原始量、计费量；token 绑定相关来源当前引用状态。
4. 执行在事务内重新计算并核对 token，只移除该批次引用，删除无其他活跃引用且非旧体系受保护的物理记录。失败不半撤销。
5. 撤销后重导重新建立完整引用；仍被其他批次引用的物理 occurrence 不被覆盖，owner 下新行使用未占用编号。
6. 验收包含 A=100、B=80 重叠+20 新增，合并 120，撤销 A 后保留 B 的 100；另含合法重复、撤销顺序、零新增、重导、过期预览及旧库保护。

## 归档

默认关闭，只有用户主动选择才将原 CSV 保存至本机确定位置；不上传，不监视目录。导入与归档分别报告结果，归档失败不得显示已保存。撤销统计批次不自动删除归档文件，也不自动清理旧归档。

实现使用浏览器原生 `showSaveFilePicker`，导入成功后还需用户点击「另存原 CSV…」。写入预览时绑定的原 `File`，保留 BOM 和字节；仅写入与关闭成功后报告已保存。浏览器不支持、取消或写入失败时明确未保存，不回滚导入。页面不把任意文件路径交给服务端；不提供目录监视或自动归档。

## 接口与验证

- `GET /api/imports/features`：当前引用能力和 Host 升级入口是否可用。
- `POST /api/imports/enable-tracking`：仅接受 `{}`；Host 原生确认展示固定 provider.db 和本次完整新备份路径，取消不写。与 provider 导入／撤销串行，不阻断本机采集。
- `POST /api/imports/revoke-preview`：仅接受 source、hash，返回影响与状态 token。
- `POST /api/imports/revoke`：仅接受 source、hash、token；状态变化返回 409，必须重新预览。新写接口保持认证、同源、请求头及 1 KiB 有限字段约束。
