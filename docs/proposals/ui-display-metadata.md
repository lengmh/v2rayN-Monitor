# #23 名称、展示归并与估算计费契约

## 数据含义

本机原始量仍是整数上传与下载。服务商计费量仍直接使用 CSV 精确小数，既不重新乘倍率，也不与本机合计。

新增的本机计费量是**名称倍率估算**：只对有采集时快照的流量片段计算。倍率策略为：节点原名没有倍率标记时按 `1` 保存，`1x`、`1倍` 也按 `1` 保存，`2x`、`0.5倍` 等按对应数值保存。编号和 VIP 字段不作为倍率，策略组标签不提供或覆盖节点倍率；相互冲突或无法解析的倍率标记保持未知。数字和结果采用整数系数与十进制尺度计算。

汇总同时返回估算覆盖的原始字节和未估算的已知字节。未采集的出站、基线前历史和采集缺口仍是未知，不能算进估算覆盖率。恢复未分时区间没有完整的名称连续性证据，因此不估算；原始恢复量的既有计入规则保持。

## 名称与身份

- 独立活动节点的原名来自已核实的 ProfileItem 显示名。
- 标准 sing-box 策略组成员按固定客户端的 `组 tag-正整数序号-Remarks` 生成规则提取原名。必须有明确且唯一的组引用；配套 `组 tag-auto` 的 URLTest 引用可与 selector 共存，其他多组引用保持未知。只拆已核实的生成结构，不任意去除括号或名称前缀。
- 原名与组标签分别保存。组标签表示配置引用，不证明某次连接经过哪个组，不作为身份归并依据。
- 展示归并仅接受服务端从既有 `instance + IndexId` 关联生成的 opaque key，并区分计量 basis。没有可靠 IndexId 的成员继续独立；不按相同名称、连接相似度或当前组选择创建身份关联。
- 同名对照使用已捕获的原名严格匹配，区分大小写与空格。旧记录没有原名快照时保留既有名称，不剥离前缀，也不补造映射。

## 可选、追加式账本扩展

基础账本的 `user_version`、原表和原 DDL 均不改变。UI 扩展只添加两张表：

| 表 | 保存内容 |
|---|---|
| `ui_display_cursors` | 上次成功观察的实体、时间戳和名称／倍率快照 |
| `ui_display_records` | 各分钟中可证明属于同一快照的整数上传／下载片段 |

基础游标、原始量和 UI 片段在同一个 SQLite 事务提交；任一写入失败全部回滚。时间戳必须与基础游标相符，防止旧版本写入后拿旧快照解释新增流量。

同一分钟可包含多份快照。查询按片段保留原名和倍率；没有证据的剩余字节单独表示未知。合计、分页、非零筛选、对照和导出使用相同投影，不用格式化值反推原始量。新增导出列为原名、组标签、倍率、估算计费量、估算覆盖字节、未估算字节。

同名节点与时间桶对照支持两种口径：原始量对照使用本机上传加下载与 CSV 原始量；计费量对照使用本机各片段的倍率估算与 CSV 计费量。名称汇总和时间桶均返回独立的估算量、覆盖原始字节和未估算字节，沿用同一查询快照，不从明细分页或当前名称重新计算。部分估算注明覆盖范围；无倍率快照显示未知，已核实的零倍率保留真实零值。列表、趋势、排序和各来源占比分母随口径一起切换；计费模式不展示未经计算的上下行计费分段，跨桶恢复量不分摊。

已有 v1/v2/v3 库正常打开时不创建扩展。全新运行目录可以在创建空账本时一起初始化。已有库须停止 Monitor，持有原数据目录 mutex 后显式执行；不会回填旧记录的名称或倍率。新的默认 1 倍规则只用于后续采集快照，已保存的未知倍率与恢复区间保持原值；新旧策略的快照边界沿用既有连续性规则。

## 受控初始化

先完成所需的 v1→v2→v3 模式迁移，再启用本扩展；此前的基础迁移执行器会拒绝包含额外表的库。当前运行模式和数据目录必须事先核实。

命令形式：

```text
V2rayN-Monitor.exe --data-dir "<原 Monitor 数据目录>" --initialize-display-metadata --backup "<全新备份路径>"
```

此命令只做离线初始化并退出，不启动采集，不启动或停止 v2rayN。Windows 调用者应等待进程结束并检查退出码，不能把进程创建成功当作初始化成功。

执行器预检只接受完整支持的原始 v1/v2/v3 库；备份必须是新文件，路径不能跨重解析点。它先用 SQLite backup 创建最新副本，然后在事务中比较全部旧值与原 DDL、追加两表、检查完整性和外键，最后提交。源在备份后变化、异常 DDL、已有扩展或已有备份均拒绝。真实运行库的初始化需要具体授权，开发验证只操作隔离副本。

初始化后继续用原模式参数启动 Monitor，例如原 v3 保留 `--probe-ledger`。第一次观察不把此前流量纳入倍率估算；原始计数连续性由既有账本负责。停机恢复量继续作为恢复未分时保存。

## 回退与验收

旧包可以读取基础历史，并忽略新增 UI 表；若旧包写入后再接回新包，没有快照证据的新增部分保持未知。回退不删除 UI 表，不自动恢复旧备份覆盖新历史。未来再做基础模式迁移时需要单独处理扩展，不绕过其预检。

开发验收包括：旧 v1/v2/v3 的全值保留、无历史回填、改名与倍率变化、同分钟混合片段、恢复区间不估算、写入故障原子回滚、旧写入者造成的快照间断、大整数与精确小数、同名不同身份、basis 隔离、原名筛选、导出及四种 UI 状态。合成测试和 CI 不能代替真实库启用及用户页面确认。
