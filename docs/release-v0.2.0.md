# v0.2.0 发布准备与升级说明

本文用于 v0.2.0 的发包与升级。正式版本、下载地址和最终摘要以经确认后发布的 Release 为准；本地候选、远端 CI、正式发布和本机启用分别记录，不互相替代。

## 三档独立下载包

三档共用相同 Monitor 源码、版本及程序文件，均为 Windows x64 自包含便携包。

| 资产名 | 随包内容 | 使用边界 |
|---|---|---|
| `v2rayn-monitor-0.2.0-basic-windows-x64.zip` | Monitor、运行时许可、升级说明和 Monitor 源码 | 使用原生 Xray 既有统计接口，不带代理核心 |
| `v2rayn-monitor-0.2.0-full-windows-x64.zip` | 基础包内容和固定 sing-box test.5 组件 | 增加当前已支持的 sing-box 普通采集；独立探测不是前置条件 |
| `v2rayn-monitor-0.2.0-extended-windows-x64.zip` | 完整包内容和固定 Xray monitor-test.1 实验组件 | 按需增加独立探测；两种核心分别核验，不能仅凭包名认定已生效 |

sing-box test.5 已含普通统计和探测能力，不为档位重新安装。普通 Xray 统计不需要换实验核心；Xray 实验核心不宣称与原定制客户端核心功能完全等价。配套文件保留于 `components/`，不在解压或启动 Monitor 时自动安装、执行或重载。

每包的 `RELEASE-MANIFEST.json` 列出来源、版本、档位、组件及文件摘要；包内 `SHA256SUMS.txt` 覆盖载荷及 manifest，不包含自身。外部 `SHA256SUMS.txt` 校验三个 ZIP。候选 manifest 明确标为 `unpublished`，不是远端信任清单。

## 本次整合的功能

- Xray 与配套 sing-box 的已支持普通路径、多出站及策略组实际成员分别记账，跨核心历史保持。
- 本机原始整数、独立服务商 CSV、原名倍率快照及原始量／计费量对照，不将不同来源相加。
- 日／周／月／年、排行／环图、历史维度、分页和导出；年→月、月→日的图表下钻。
- 历史页首次失败或空结果的有界补查，更新时间按钮可主动刷新，保留筛选和会话。
- CSV 增量防重、批次引用和有确认的撤销、可选另存原 CSV；不强制升级旧 provider。
- 可选联动快捷方式、配套核心下载／安装／恢复、原生确认、单步离线账本交接和运行能力核验。
- 可重建的日级历史汇总：历史结果复用，源变更只使受影响日期失效；当天和不适用查询回退原始路径。

普通采集、页面、CSV、恢复、资源与安装器沿用已确认的分层证据，见在线 [支持矩阵](https://github.com/lengmh/v2rayN-Monitor/blob/main/docs/compatibility.md) 及 [验收清单](https://github.com/lengmh/v2rayN-Monitor/blob/main/docs/acceptance-reconciliation.md)。G4 依据用户确认的隔离范围收口，不能写成已经执行真实客户端安装／重载。S5.8 按已交付范围验收，不再单独安排。

## 支持与计量边界

- Windows x64，固定 v2rayN 7.25.1 标准配置及已核实核心组合；具体路径见支持矩阵。不新增 TUN、代理链、多个客户端或任意配置来源。
- 首接只建基线，未知、缺口和停机恢复不补成零，不按节点同名合并身份。
- 倍率使用采集时证据；旧未知不回填，恢复未分时不估算。服务商计费量保留 CSV 的精确十进制值，不重算、不取整。
- 探测是已说明计量点的流字节，不是服务商账单；Xray 出站量与探测可能重叠，不相加或直接相减。DNS、远程规则集等未覆盖请求保留说明，不增加本次发布待验。
- 日级汇总先覆盖显式初始化过的 v3、`local_proxy`、无名称筛选、上海时区、月／年非零首屏。其他筛选和后续页仍可走原始路径。空汇总首次查询及构建是一次性准备成本，不能称为全部访问均已加速。

## 已有数据升级

**先确认数据目录和账本版本，再替换程序。不要把新程序直接解压覆盖数据。**

1. 从现有启动参数核实 `--data-dir`、账本模式和唯一写入者。程序所在目录不一定是数据目录。
2. 只退出 Monitor，保留 v2rayN／代理核心运行。对历史、provider、设置及关联文件创建新的完整备份；活跃 SQLite 使用一致性备份，不单独复制主库忽略 WAL。
3. 将候选包先解压到新目录，核对外部 ZIP 摘要和包内文件摘要。
4. 程序替换时保留数据，沿用正确的数据目录和模式。已有 v3 继续 `--probe-ledger`，已有 v2 继续 `--scope-ledger`；已有 v1 仍可按原入口打开。
5. 需要提升账本版本时，另执行有新备份、停写和核对的单步离线交接。普通启动不自动迁移；不能按下载档位降级 v3。
6. 重新启动后核对单实例、原历史、服务商记录、设置和持续采集。恢复旧程序时保留新增历史，不用旧备份直接覆盖新数据。

旧 provider 的原导入记录继续可读。批次引用未启用时，旧批次不可撤销；不能为了显示新按钮回填不存在的引用。默认不保存原 CSV 文件，数据库中的导入记录不等同于原文件字节。

### 本机两目录合并的交付顺序

S5.4完成后计划覆盖旧程序并合并旧版与预览包的全部数据，包含服务商CSV导入。该具体数据操作在发布后安排，不由本打包脚本执行。

1. 保留两个原始数据目录，分别建立一致性副本和摘要清单。
2. 按版本迁移旧历史副本，再按可靠身份核对分钟、未分时、缺口、展示证据和持久状态。重复记录不叠加，冲突不静默覆盖；历史游标不能代替当前有效采集游标。
3. 合并 provider 的原始记录和导入批次，保留来源、文件摘要、合法重复次数及精确计费值。若存在批次引用／撤销记录，也须保留，不能通过重导 CSV 丢失原批次。
4. 原设置、原 CSV 和其他导入附件分别留档。运行默认值若有冲突，明确选择并保留另一份原值；不凭同名猜测同一节点或同一服务商来源。
5. 在全新隔离目标验证完整并集、重开及当前页面可见性。到真正切换窗口时重新停写、备份和核对最新尾部，再覆盖程序、切换数据绑定。

只有隔离合并及最新停写核对通过后，才把合并结果作为正式数据启用；失败保留两个原目录及原入口，不预先覆盖任一来源。

## 离线候选准备

`scripts/prepare_release.py` 接收固定源码 ZIP、已封存的 Windows 发布目录／构建回执，以及生产固定目录对应的两份独立组件 ZIP。它不联网、不执行 EXE、不安装依赖、不写真实数据，也不发布。输入文件或组件摘要不匹配、混入运行数据、输出目录已存在时拒绝。

```text
python scripts/prepare_release.py --publish-dir <sealed-win-x64-publish> --runtime-input <runtime-input.json> --source-archive <fixed-monitor-source.zip> --component-dir <fixed-component-zips> --output <new-candidate-directory>
```

构建回执记录产品版本、来源提交、固定源码归档 SHA256、自包含平台、构建来源和全部发布文件的长度／SHA256；来源应由实际构建步骤核实。CI 产物还记录精确运行、artifact 和下载归档摘要；版本覆盖仅在实际使用时记录，否则为空，不能把本地构建参数写成 CI 行为。候选附带固定 Monitor 源码归档，打包脚本本身也记录摘要。最终提交、CI、发布资产与候选的对应关系须在发布前核对。

## 许可与来源

Monitor 原创代码采用 MIT；运行时许可位于 `licenses/`。full／extended 随附的 sing-box 为独立 GPL-3.0-or-later 程序，包含完整 COPYING、固定上游归档、四层补丁及构建记录；extended 的 Xray 实验组件采用 MPL-2.0，同样保留固定上游、补丁、回归源文件和构建记录。组件各自的元数据保留原构建版本，不冒充由本次 Monitor 构建重新生成。

候选不包含真实历史库、服务商 CSV、节点资料、完整核心配置、订阅或凭据。新增数据合并的本机回执只留专用过程目录，不进入发布包或公开仓库。
