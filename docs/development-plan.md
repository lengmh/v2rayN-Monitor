## 1. 产品目标与不变约束

这是一个以 **v2rayN 本机数据为主要来源**的 Windows 节点流量历史统计工具。独立宿主在托盘常驻，HTML 页面用于查看、筛选、导入、导出和设置。用户即使从不导入服务商 CSV，也必须获得完整的自动采集与日/周/月/年分析体验。

主来源为正在运行的 v2rayN 所管理内核的统计接口；v2rayN 的配置库只辅助识别节点和检查基线，不预设其落盘统计是实时、原始字节或完整每日历史。服务商 CSV 是偶尔导入的独立补充账本，不能反客为主。TrafficMonitor 插件仅是可选显示入口。

首版不做：服务商定时抓取/导入提醒、三天滚动完整性平台、远端服务、云账户、跨设备同步、抓包驱动、代理管理器替代品、任意代理链的精确出口统计。无需为未来插件预先建设通用插件平台。

## 3. 最小架构与技术决策

```text
v2rayN 配置（只读） ── 节点/实例/运行会话 ─┐
                                         ├─ 采集与原子记账 ─ SQLite ─ 本地 API ─ HTML
Xray / sing-box（只读统计，不重置计数） ───┘          │
                                                    ├─ 独立托盘宿主
服务商 CSV（用户偶尔导入） ── 独立账本 ──────────────┤
                                                    └─ 只读摘要 ─ 可选 TrafficMonitor 插件
```

选择一个 .NET 10 Windows 进程，托盘使用 WinForms 的轻量宿主，本地接口使用 ASP.NET Core，历史存储使用 SQLite。前端采用 HTML + TypeScript，Vite 构建；图表可用 ECharts，依赖实现时锁版，资源随应用打包，不通过 CDN 加载。

**首版默认在系统浏览器打开本地 HTML**，关闭页面不影响采集。不把 WebView2 作为运行前提；确有独立窗口需求时再作为宿主选项。这样避免同时维护两套界面和额外浏览器进程。

计划采样周期为 1 秒；数据库正常情况下每次采样事务提交，批量优化必须保留明确的未提交窗口。长期查询依赖分钟/小时及日汇总，不永久积累每秒记录。实际参数由 S4.3 的有限测量确定。

## 4. 记账和展示规则

### 4.1 必须保留的语义

本机“上传/下载”按客户端方向定义，“合计”是两者之和；本机值是内核计量口径，不宣称等于网卡包含全部协议开销的线速流量，也不宣称等于服务商套餐扣减。

主键使用 `instance_id + v2rayN IndexId`，不能使用节点名称。节点改名继续原历史，删除节点仍能查旧记录；订阅重建导致 ID 改变时先保留两者，只有可靠证据或用户确认后建立关联。服务商节点另有来源命名空间。

本机与服务商原始量使用整数 bytes；服务商计费量按 CSV 保留精确十进制数值，不取整、不按倍率重算。UI 可切换 GB/GiB，但不更改底层量；大整数通过十进制字符串传给 JavaScript，计算需要时用 BigInt，只有图表坐标使用受控浮点表示。界面格式化数值不能成为二次记账输入。

### 4.2 采样边界

同一有效会话且计数连续时，增量为 `当前累计 - 已提交累计`。首次接入只建立基线，之前的累计不能全部记到今天。每笔增量、汇总和游标原子提交，失败时不推进游标。

计数减小、核心代次变化或映射竞争时不套用普通差分。上下行任一方向都要检查重置；不能只检查下载方向。确认连续的断连区间可以恢复累计；无法确认时标记缺口。累计总量已恢复而跨日分布不可知，保留“恢复但未分时”量，不能编造每日分布。

跨午夜的短采样区间可按约定的时间比例分配，整数余数在同一区间内分配以守恒，并标明分时近似；较长缺口不做假精确分配。不得让“未分时量”在总览与日/周/月/年之和的差异毫无说明。

### 4.3 归属和复杂配置

普通单节点采用按 v2rayN 活动配置归属的口径，实例与 IndexId 组成历史身份，连接参数相同的不同配置仍分账。该口径不承诺从核心侧独立辨别完全相同的逻辑配置；采样前后选择、有效配置与核心代次须一致，切换先建新基线。策略组、代理链和并发出站需要另外的映射证据。不能把全局 `/traffic` 值无条件归到当前选中节点；不能把多跳链路每一跳相加成总使用量；不能把 inbound 与 outbound 相加。

质量至少区分：正常记录、估算、未归属、采集缺口、恢复但未分时。缺口不是零流量；无计费数据不是计费量为零。

### 4.4 服务商补充数据

用户提供的格式为 `node_name, rate, origin_traffic, origin_x_rate, traffic, log_time`。服务商原始量与服务商计费量分开存储，优先尊重数值列，不根据显示文本反算字节；倍率为 0 仍可能有原始使用量。

没有 IP、设备、方向则保存为未知，不推断为本机。服务商与本机同屏对比但不叠加、不覆盖；差值不是具体设备归属证据。每次只能导出三天只是一项导入能力限制，不产生任何周期任务或默认提醒。

无稳定记录 ID 的重叠导出无法在任意数据修订规则下证明完美去重。先实现同文件哈希去重；对已确认稳定语义的快照使用行签名多重集合比较，保留合法重复；冲突显式提示。不能把最早/最晚记录时间误当成完整覆盖区间。

一个任务节点是验收和报告单位，不强制一节点一个 PR。相邻且具有相同目标的节点可以作为一个小 PR，但不让一个 PR 横跨所有阶段。

**实施：** 记录文件哈希和批次；同一文件重复导入不增加账本。无稳定记录 ID 时，对确认属于同一来源、同一导出语义的重叠文件使用规范化行签名与出现次数比较，保留文件内合法重复；无法判断修订或语义时提示冲突。

**产物：** 服务商独立账本与导入批次；预览新增/重叠/异常结果。

**验收：** 同文件重复不双算；同一文件的两条合法相同行保留；重叠批次在已约定语义下不叠加；失败不半入账。没有记录 ID 不能宣称普适精确去重。

**收口：** 不建设三天滚动覆盖平台；记录最早/最晚出现时间不等于证明整个区间完整。

**进度依据：** Issue #11 / PR #14 的规范化计费行及出现次数增量导入已随 v0.1.1（351fdfc）发布；合成回归和用户整体确认已有记录，不宣称无记录 ID 时的普适去重。

#### S6.3 · 提供来源分离的统计与对照

**状态：** done。**依赖：** S6.2、S3.4。

**实施：** 主页面仍默认本机。用户主动选择服务商原始量、计费量或并排对照；本机未知计费值显示不适用，不显示 0。按名称完全相同提供显式同名对照，不写入身份关联，不自动合并节点；无法匹配时保留服务商独立节点。

**产物：** 服务商筛选与显式同名并排对照；来源与计量口径说明（不建立跨来源身份映射）。

2026-10-11 用户选择先统一界面并保留来源口径：已实现来源切换、服务商节点排行/趋势/明细和独立导出。跨来源映射与并排对照不属于本次 Issue #5 范围，未把同名节点自动合并。

随后以独立 Issue #8 / PR 实现简单同名对照，小时为最小粒度并支持周/月；本轮按显示名称分组仅用于查看，不写入身份关联，保留单边节点和未知值。不要求建立复杂映射系统。

**验收：** 本机与服务商不求和、不互相覆盖；没有设备数据不能把差额归到本机或其他具体设备；零倍率节点仍显示服务商原始使用量。

**收口：** 不把 CSV 差额当作丢包、漏计或他人使用的确定证据。

**进度依据：** Issue #5/#8 的统一来源统计与同名对照已随 v0.1.0 / PR #9 发布；v0.1.1 补齐日期默认分桶。依据用户整体确认收口，范围以显式同名查看为准，不包含自动身份映射。

#### S6.4 · 完成 CSV 批次管理增强并纳入 v0.2.0

**状态：** planned。**依赖：** S6.3。

**实施：** 在现有批次记录和查看结果上增加撤销，撤销前展示影响并要求明确确认。先明确增量去重记录与批次的关联，不能误删其他有效批次共享记录；旧批次缺少关联信息时明确限制，不按时间重叠猜测。提供用户自选的原文件本地归档，默认不开启、不上传。需要 Schema 迁移时先提交可审阅方案，不直接修改真实库。

**产物：** 导入历史与批次撤销；可选 CSV 原文件本地归档；v0.2.0 导入边界与升级说明。

**进度依据：** 已登记独立 Issue #16，本轮仅完成需求登记，尚未开始实现。

**验收：** 撤销前能确认影响范围；撤销某批次不误删其他批次共享记录或本机历史，失败不半撤销。原文件归档由用户选择且只保存在本地；不使用 CSV 时本机功能不受影响。三天导出限制不产生强制任务。

**收口：** 功能到此为止，除非有真实需求再增加服务商扩展。

## 7. PR 与 checkpoint 执行方式

默认每个 work turn 只完成一个明确 checkpoint：`核实 HEAD/当前阶段 → 一个有界任务批次 → 针对性验证 → commit/push → 检查该提交 CI → checkpoint`。最多两个 checkpoint；达到停点先汇报，不在一次会话反复展开多轮新问题。

建议分组：S0 独立验证报告；S1 一个骨架 PR；S2 的持续计量与切换/重连可分两个 PR；S3 的周期查询与 HTML 页面可分两个 PR；S4 一个收口 PR。扩展阶段按实际变更拆分，而不是预先生成大量空分支。

状态只用 `planned / in_progress / blocked / done / deferred`。`done` 必须有对应产物和验收证据；源码核读、合成测试、Windows 实机测试分别注明。CI 只认确切提交，不能用旧提交绿灯作为新提交已验证的证据。

开发先打通主路径。边界只优先处理三类：影响计量正确性、会损坏已保存数据、触及真实安全边界。bug 修复先有最短复现与回归；新功能采用与风险匹配的测试，不强制穷举。不存在固定覆盖率或测试数门槛，不对尚未支持的模式提前做全量矩阵。

最重要的停止条件：首个可用版本已经达到预设验收后，停止向 v0.1 塞入新功能。后续“可能有用”但没有真实需求的功能记入 backlog。
