## 1. 产品目标与不变约束

这是一个以 **v2rayN 本机数据为主要来源**的 Windows 节点流量历史统计工具。独立宿主在托盘常驻，HTML 页面用于查看、筛选、导入、导出和设置。用户即使从不导入服务商 CSV，也必须获得完整的自动采集与日/周/月/年分析体验。

主来源为正在运行的 v2rayN 所管理内核的统计接口；v2rayN 的配置库只辅助识别节点和检查基线，不预设其落盘统计是实时、原始字节或完整每日历史。服务商 CSV 是偶尔导入的独立补充账本，不能反客为主。TrafficMonitor 插件仅是可选显示入口。

首版不做：服务商定时抓取/导入提醒、三天滚动完整性平台、远端服务、云账户、跨设备同步、抓包驱动、代理管理器替代品、任意代理链的精确出口统计。无需为未来插件预先建设通用插件平台。

## 2. 本轮已经核实什么

已按固定源码提交核读 Xray 与 sing-box 两条 v2rayN 统计路径，以及节点归属管理逻辑。核读确认的只是代码行为，不等于用户电脑上已经通过验证。

| 核实项 | 对计划的约束 | 证据 |
|---|---|---|
| Xray 路径读取 `/debug/vars`，按出站取数后做缩放和差分 | Monitor 优先直接保留原始字节，不照搬界面单位 | [R1]、[R5] |
| sing-box 路径读取 WebSocket `/traffic`，存在不同的单位处理 | 必须先证明目标接口数值语义和流量范围，再实现记账 | [R2]、[R6] |
| 统计管理以当前配置 IndexId 更新，今日量会跨日重置 | 必须独立保存历史；活动配置不必然是最终出口节点 | [R3] |
| TrafficMonitor 有显示、数据刷新和鼠标回调接口 | 插件可后置；不需要把完整数据管理放进 DLL | [R4] |
| .NET 8 将于 2026-11-10 结束支持，.NET 10 为在支持的 LTS | 新项目采用 .NET 10，而不是沿用早先讨论中的 .NET 8 | [R7] |

引用、精确提交及核查范围见 [来源与验证记录](sources.md)。当前支持范围及各层级验证结果见支持矩阵；CSV 采用固定六字段预设，不公开真实记录。

## 3. 最小架构与技术决策

```text
v2rayN 配置（只读） ── 节点/实例/运行会话 ─┐
                                         ├─ 采集与原子记账 ─ SQLite ─ 本地 API ─ HTML
Xray / sing-box（只读统计，不重置计数） ───┘          │
                                                    ├─ 独立托盘宿主
服务商 CSV（用户偶尔导入） ── 独立账本 ──────────────┤
                                                    └─ 只读摘要 ─ 可选 TrafficMonitor 插件
```

选择一个 .NET 10 Windows 进程，托盘使用 WinForms 的轻量宿主，本地接口使用 ASP.NET Core，历史存储使用 SQLite。前端采用 HTML + TypeScript，Vite 构建；图表可用 ECharts，依赖实现时锁版，资源随应用打包，不通过 CDN 加载。

**首版默认在系统浏览器打开本地 HTML**，关闭页面不影响采集。不把 WebView2 作为运行前提；确有独立窗口需求时再作为宿主选项。这样避免同时维护两套界面和额外浏览器进程。

计划采样周期为 1 秒；数据库正常情况下每次采样事务提交，批量优化必须保留明确的未提交窗口。长期查询依赖分钟/小时及日汇总，不永久积累每秒记录。实际参数由 S4.3 的有限测量确定。

## 4. 记账和展示规则

### 4.1 必须保留的语义

本机“上传/下载”按客户端方向定义，“合计”是两者之和；本机值是内核计量口径，不宣称等于网卡包含全部协议开销的线速流量，也不宣称等于服务商套餐扣减。

主键使用 `instance_id + v2rayN IndexId`，不能使用节点名称。节点改名继续原历史，删除节点仍能查旧记录；订阅重建导致 ID 改变时先保留两者，只有可靠证据或用户确认后建立关联。服务商节点另有来源命名空间。

本机与服务商原始量使用整数 bytes；服务商计费量按 CSV 保留精确十进制数值，不取整、不按倍率重算。UI 可切换 GB/GiB，但不更改底层量；大整数通过十进制字符串传给 JavaScript，计算需要时用 BigInt，只有图表坐标使用受控浮点表示。界面格式化数值不能成为二次记账输入。

### 4.2 采样边界

同一有效会话且计数连续时，增量为 `当前累计 - 已提交累计`。首次接入只建立基线，之前的累计不能全部记到今天。每笔增量、汇总和游标原子提交，失败时不推进游标。

计数减小、核心代次变化或映射竞争时不套用普通差分。上下行任一方向都要检查重置；不能只检查下载方向。确认连续的断连区间可以恢复累计；无法确认时标记缺口。累计总量已恢复而跨日分布不可知，保留“恢复但未分时”量，不能编造每日分布。

跨午夜的短采样区间可按约定的时间比例分配，整数余数在同一区间内分配以守恒，并标明分时近似；较长缺口不做假精确分配。不得让“未分时量”在总览与日/周/月/年之和的差异毫无说明。

### 4.3 归属和复杂配置

普通单节点采用按 v2rayN 活动配置归属的口径，实例与 IndexId 组成历史身份，连接参数相同的不同配置仍分账。该口径不承诺从核心侧独立辨别完全相同的逻辑配置；采样前后选择、有效配置与核心代次须一致，切换先建新基线。策略组、代理链和并发出站需要另外的映射证据。不能把全局 `/traffic` 值无条件归到当前选中节点；不能把多跳链路每一跳相加成总使用量；不能把 inbound 与 outbound 相加。

质量至少区分：正常记录、估算、未归属、采集缺口、恢复但未分时。缺口不是零流量；无计费数据不是计费量为零。

### 4.4 服务商补充数据

用户提供的格式为 `node_name, rate, origin_traffic, origin_x_rate, traffic, log_time`。服务商原始量与服务商计费量分开存储，优先尊重数值列，不根据显示文本反算字节；倍率为 0 仍可能有原始使用量。

没有 IP、设备、方向则保存为未知，不推断为本机。服务商与本机同屏对比但不叠加、不覆盖；差值不是具体设备归属证据。每次只能导出三天只是一项导入能力限制，不产生任何周期任务或默认提醒。

无稳定记录 ID 的重叠导出无法在任意数据修订规则下证明完美去重。先实现同文件哈希去重；对已确认稳定语义的快照使用行签名多重集合比较，保留合法重复；冲突显式提示。不能把最早/最晚记录时间误当成完整覆盖区间。

| 阶段 | 目标 | 任务节点 | 交付 |

主线为 `S0 → S1 → S2 → S3 → S4（v0.1.0）`。S5 的第二内核、S6 的服务商导入和 S7 的 TrafficMonitor 插件均不能阻塞首版主线。S6、S7 技术上仅依赖 S4，可在第一版发布后按实际需要调换，版本名称随真实实施顺序调整。

默认 Xray 先实现，不代表首版必须忽略用户实际主内核：S0 若确定用户主要用 sing-box，且有可靠累计路径，则交换 S2 与 S5 的适配顺序，存储/页面/验收标准不变。**不能因为主内核有难点，就转向先做 CSV 产品。**

一个任务节点是验收和报告单位，不强制一节点一个 PR。相邻且具有相同目标的节点可以作为一个小 PR，但不让一个 PR 横跨所有阶段。

## 6. 逐阶段、逐节点实施清单

### S0 · 采集可行性与支持边界

**阶段目标：** 用实际 Windows 环境证明“能读到什么、单位是什么、归属到谁”，不先做界面。

**阶段交付：** 不发版；冻结首个可验证环境

#### S0.1 · 冻结实机环境与只读发现路径

**状态：** `done`；依赖：无。

**实施：** 记录用户实际安装的 v2rayN 版本、内核版本、Windows 版本、普通代理或 TUN 模式。确认程序目录、有效运行配置、统计端口和节点列表的读取路径；自动发现失败允许用户指定目录，不做全盘扫描。源码核读与实机验证分别记录。

**产物：** docs/compatibility.md 的首条环境记录；脱敏后的发现结果与复现步骤。

**验收：** 手动指定一个 v2rayN 实例后，能确定正在运行的内核及其回环地址；无统计接口时给出具体设置指引；日志没有订阅地址、口令和真实完整配置。

**收口：** 没有可用 Windows 或目标安装时记为 BLOCKED，不把源码可读标成集成已通过。

#### S0.2 · 验证 Xray 原始累计计数

**状态：** `done`；依赖：S0.1。

**实施：** 只读调用实际启用的 metrics 接口，按 outbound 标签观察上下行计数。验证原始单位、单调递增性、direct/proxy 区分、停流和核心重启。保留原始字节，不照搬界面的整数缩放；不调用 reset=true 的统计查询。

**产物：** Xray 最小探测工具及合成响应样本；Xray 指标语义与计数口径记录。

**验收：** 用受控上传、下载和空闲场景证明两个方向变化正确；同一会话两端原始计数差与探测增量严格相等。应用载荷大小仅作合理性核对，不要求等于服务商计费值。

**收口：** 若只能取得总量，不能宣称已得到逐节点统计；记录缺失条件后进入 S0.4 决策。

#### S0.3 · 验证 sing-box 可用计数与粒度

**状态：** `done`；依赖：S0.1。

**实施：** 先核对当前实装的 v2rayN、sing-box 精确版本及 AnyTLS 普通单节点生成配置，再验证可用统计接口、原始单位、累计/速率语义、进程代次和代理流量范围。累计计数优先，不把速率冒充累计字节，不推断已消失短连接的流量；不擅自改写配置或重启核心。

**产物：** sing-box 能力探测结果；可用路径、估算路径和不支持路径对照。

**验收：** 明确输出能力等级：逐出站累计、活动配置累计、速度估算或不可用。不能用连接轮询推断已消失的短连接流量；速度乘时间的结果必须标为估算。

**收口：** 本轮只验证路径，不承诺所有构建与模式。用户未安装或不使用该内核时可 deferred，待 S5 再验证，不阻塞已证明的主内核，也不改以 CSV 作为主来源。

#### S0.4 · 冻结节点归属和首版支持范围

**状态：** `done`；依赖：S0.2。

**实施：** 证明运行实例、核心会话、outbound 标签与 v2rayN IndexId 的关系。区分普通单节点、TUN、策略组、代理链、多出站。首版只纳入能够验证归属的模式，复杂模式显示活动配置或未知归属。确认第一内核和默认时区。

**产物：** 首版支持矩阵；docs/architecture.md 的已决策部分；S0 checkpoint 与后续顺序。

**验收：** 在 A/B 两节点切换的受控场景中能解释归属过程；无法辨识最终出口时不按名称猜测。至少一条主内核可靠路径通过，才允许 S2 进入产品化。

**收口：** 默认依赖 S0.2；若第一内核换为 sing-box，则同步改为依赖 S0.3，未选内核的探测可 deferred，不阻塞主线。一次有界决策即可收口，不为了代理链重写内核。

### S1 · 最小运行与存储骨架

**阶段目标：** 建立一个进程、一个数据库和可替换采集适配器，不提前搭通用插件框架。

**阶段交付：** 内部开发基线

#### S1.1 · 创建最小桌面宿主与开发流水线

**状态：** `done`；依赖：S0.4。

**实施：** 建立 .NET 10 Windows 托盘宿主、核心库、测试项目和 HTML/TypeScript 前端目录。宿主同进程运行采集服务与本地 HTTP 服务，浏览器按需打开。建立 Windows 构建和当前单测的 CI，不要求 WebView2、Electron 或 Windows 系统服务。

**产物：** src/Host、src/Core、web 的最小可运行骨架；Windows 构建及当前测试 workflow。

**验收：** 启动后出现托盘，点击可打开本地空白控制台；关闭页面不结束宿主；退出托盘释放端口。CI 实际构建已有代码，不用空测试制造绿色状态。

**收口：** 无框架横向比较工程；仅在验证结果表明不适用时更改已选技术。

#### S1.2 · 定义最小采样与身份契约

**状态：** `done`；依赖：S1.1。

**实施：** 定义实例、节点、核心会话、采样时间、上下行原始字节、计数来源、归属级别及质量标记。节点主键采用实例 ID + IndexId；名称只作显示。统一当前适配器返回累计计数还是区间增量。

**产物：** 核心数据类型与一个采集适配器接口；协议字段和错误状态说明。

**验收：** 用合成数据证明不同实例的同名节点不会合并，重命名不丢历史，字节数全链路不提前转浮点。只抽象当前两种内核真正共享的部分。

**收口：** 不建立通用驱动注册中心、规则语言或第三方插件 SDK。

#### S1.3 · 实现 SQLite 原子记账与采样游标

**状态：** `done`；依赖：S1.2。

**实施：** 创建本机账本、节点表、会话游标、采集状态/缺口表和分钟汇总。将增量入账、汇总更新、游标推进放进同一事务；先保留所需的短期诊断记录，不永久存每秒样本。

**产物：** 数据库迁移 v1；可重放的记账服务与查询入口。

**验收：** 同一采样重放不重复计费；写入失败不推进游标；重启后读取最后提交游标；旧累计首次接入仅建立基线，不全部算入今天。

**收口：** 只验证真实写入边界与回归，不开展无限故障注入或自制数据库恢复框架。

#### S1.4 · 接入本地页面边界和最小诊断

**状态：** `done`；依赖：S1.1、S1.3。

**实施：** 只监听 127.0.0.1，提供运行状态、当前实例和已记录总量接口。设置会话校验及 Host/Origin 校验，写操作不用 GET；日志记录版本、事件和错误而不记录凭证。静态资源离线打包。

**产物：** /api/status 与最小会话建立流程；脱敏诊断输出。

**验收：** 普通外部网页不能读取本地账本或触发写操作；无鉴权访问被拒绝；浏览器控制台显示真实状态，不把离线显示成零流量。

**收口：** 安全边界做到本地工具所需即可，不引入云账户、复杂权限系统或远程管理。

### S2 · 第一条可靠的本机采集链

**阶段目标：** 默认先接 Xray；若 S0 证明用户主要使用 sing-box 且其可靠路径已通，可交换 S2/S5 的内核顺序。

**阶段交付：** 本机采集内测版

### S6 · 服务商 CSV 偶尔补充

**阶段目标：** 离线导入、分账展示，不设置每两天导入要求，不把导入完整性变成日常主流程。

**阶段交付：** v0.2.0：CSV 批次管理增强（基础能力已交付）

#### S6.1 · 实现当前 CSV 格式的可选预览

**状态：** `done`；依赖：S4.4。

**实施：** 只支持已提供的六字段预设作为首版导入能力：node_name、rate、origin_traffic、origin_x_rate、traffic、log_time。HTML 拖放/选择文件，确认来源账户与无时区时间的解释。IP、设备和上下行允许缺失。

**产物：** 服务商导入预览页；完全合成的 CSV 测试样本。

**验收：** 数值以原始数值列为准，traffic 仅展示；保留原始量、倍率和计费量，不重新覆盖供应商给出的计费值。无设备/方向记录仍可导入且保持未知。

**收口：** 不做通用 CSV 映射引擎、自动下载、登录抓取、定期提醒或目录监视。

#### S6.2 · 实现事务导入与有限去重

**状态：** `done`；依赖：S6.1。

**实施：** 记录文件哈希和批次；同一文件重复导入不增加账本。无稳定记录 ID 时，对确认属于同一来源、同一导出语义的重叠文件使用规范化行签名与出现次数比较，保留文件内合法重复；无法判断修订或语义时提示冲突。

**产物：** 服务商独立账本与导入批次；预览新增/重叠/异常结果。

**验收：** 同文件重复不双算；同一文件的两条合法相同行保留；重叠批次在已约定语义下不叠加；失败不半入账。没有记录 ID 不能宣称普适精确去重。

**收口：** 不建设三天滚动覆盖平台；记录最早/最晚出现时间不等于证明整个区间完整。

#### S6.3 · 提供来源分离的统计与对照

**状态：** `done`；依赖：S6.2、S3.4。

**实施：** 主页面仍默认本机。用户主动选择服务商原始量、计费量或并排对照；本机未知计费值显示不适用，不显示 0。按名称完全相同提供显式同名对照，不写入身份关联，不自动合并节点；无法匹配时保留服务商独立节点。

**产物：** 服务商筛选与显式同名并排对照；来源与计量口径说明（不建立跨来源身份映射）。

**验收：** 本机与服务商不求和、不互相覆盖；没有设备数据不能把差额归到本机或其他具体设备；零倍率节点仍显示服务商原始使用量。

**收口：** 不把 CSV 差额当作丢包、漏计或他人使用的确定证据。

#### S6.4 · 完成 CSV 批次管理增强并纳入 v0.2.0

**状态：** `done`；依赖：S6.3。

**实施：** 完整批次occurrence引用、撤销预览/token重验/事务保护、零增量及重导语义已实现；旧库仅显式原生确认及新备份后启用，旧批次不猜引用。原File本地归档默认关闭，由浏览器显式另存，成功关闭后才报告已保存。源码与隔离验证、原生交互及页面使用验收完成；旧库不强制升级。

**产物：** 导入历史与批次撤销；可选 CSV 原文件本地归档；v0.2.0 导入边界与升级说明。

**验收：** 撤销前能确认影响范围；撤销某批次不误删其他批次共享记录或本机历史，失败不半撤销。原文件归档由用户选择且只保存在本地；不使用 CSV 时本机功能不受影响。三天导出限制不产生强制任务。

**收口：** 功能到此为止，除非有真实需求再增加服务商扩展。

详细方案见 [提案](proposals/provider-batch-references.md)。

## 7. PR 与 checkpoint 执行方式

默认每个 work turn 只完成一个明确 checkpoint：`核实 HEAD/当前阶段 → 一个有界任务批次 → 针对性验证 → commit/push → 检查该提交 CI → checkpoint`。最多两个 checkpoint；达到停点先汇报，不在一次会话反复展开多轮新问题。

建议分组：S0 独立验证报告；S1 一个骨架 PR；S2 的持续计量与切换/重连可分两个 PR；S3 的周期查询与 HTML 页面可分两个 PR；S4 一个收口 PR。扩展阶段按实际变更拆分，而不是预先生成大量空分支。

状态只用 `planned / in_progress / blocked / done / deferred`。`done` 必须有对应产物和验收证据；源码核读、合成测试、Windows 实机测试分别注明。CI 只认确切提交，不能用旧提交绿灯作为新提交已验证的证据。

开发先打通主路径。边界只优先处理三类：影响计量正确性、会损坏已保存数据、触及真实安全边界。bug 修复先有最短复现与回归；新功能采用与风险匹配的测试，不强制穷举。不存在固定覆盖率或测试数门槛，不对尚未支持的模式提前做全量矩阵。

最重要的停止条件：首个可用版本已经达到预设验收后，停止向 v0.1 塞入新功能。后续“可能有用”但没有真实需求的功能记入 backlog。
